# Mission 2: 신고자와 119대원 발화 분류

## 현재 최고 검증 기록

**ResNet18 30% + ResNet34 30% + WavLM 4층 40%의 신고자 확률 결합으로 공식 Validation Accuracy 91.972%를 기록했다. 최종 판정 임계값은 0.5다.**

2026-10-12 확인: 세 모델을 1/3씩 결합한 구성이 아니다. 30:30:40은 공식 Validation의 비율별 결과를 비교한 **뒤 선택한 구성**이며, 결과 확인 전 확정한 비율이라고 설명하지 않는다. 실제 가중치를 이용한 통합 제출 추론 검증은 WavLM 가중치 수령 후 진행해야 한다.

ResNet18/34 파라미터는 각각 **11,169,858 / 21,278,018개**, WavLM4를 포함한 총합은 **70,617,942개**다. 실제 비교 실행에서 ResNet 두 모델은 **Tesla T4, batch 128**로 추론했다. WavLM은 RTX 5060 Laptop GPU, batch 16에서 생성한 확률을 가져왔으므로 **세 모델의 동일 환경 통합 추론 시간은 아직 미측정**이다. [최신 확인 기록](results/resnet_wavlm_ensemble_20261011/verification_20261012.md)을 참고한다.

## 1. 문제와 데이터

시작과 끝이 주어진 **한 사람의 한 발화**를 `speaker=0`(119대원), `speaker=1`(신고자)로 분류한다. 화자 신원 확인, 음성 분리, 위급도 분류가 목적은 아니다. Accuracy는 전체 정답 비율, 클래스별 Recall은 실제 해당 클래스 중 정답 비율이다.

| 항목 | Training | 공식 Validation |
|---|---:|---:|
| 통화 수 | 29,200 | 3,640 |
| 발화 수 | 889,358 | 111,947 |
| 119대원 발화 | 427,161 | 53,845 |
| 신고자 발화 | 462,197 | 58,102 |

서울 지역 데이터의 WAV·JSON 매칭과 8kHz/mono/PCM16 형식을 확인했다. [EDA 보고서](eda/REPORT.md). 모델은 JSON `startAt/endAt`으로 추출한 발화 음성만 사용한다. 전사 텍스트·주소·발화 순서·파일명·정답 speaker를 입력 특징으로 쓰지 않는다. ID는 결과 정렬과 감사에만 사용한다.

ResNet은 Training 889,358발화로 학습했다. 현재 WavLM은 Training 통화를 seed 20261010으로 90:10 분리한 후 fit에서 100,000발화, 내부 dev에서 4,000발화를 사용했다. 공식 Validation은 WavLM 학습과 epoch 선택에 넣지 않았다. 서로 다른 통화에 같은 사람이 존재하는지는 확인하지 못했다.

## 2. 전처리: 서로 다른 두 음성 표현

### ResNet: `first_plus_whole`

1. JSON 시각(ms)으로 한 발화를 자른다.
2. 앞 1.5초를 64 Mel 대역, 24프레임의 log-Mel로 만든다. 짧으면 뒤에 0을 채운다.
3. 긴 발화 전체의 log-Mel을 시간축 24구간으로 평균한다. 1.5초 이하이면 앞부분 특징을 재사용한다.
4. 두 표현을 붙여 `[64,48]`로 만든다. 전체 통화가 아니라 해당 발화 전체를 요약한다.
5. `clip((mel+80)/80,0,1)` 정규화 후 전체 요약 평균을 계산한다. `round(feature*255)`로 uint8 저장하고 학습·추론에서는 float32/255로 복원한다.

앞부분의 비교적 세밀한 패턴과 뒤쪽 음성을 포함한 전체 경향을 작은 입력에 함께 반영하려는 설계다. 사전 계산은 Colab 전송량과 반복 처리량을 줄인다. 다만 평균 요약과 양자화로 세부 시간 변화가 손실될 수 있다. `[64,48]`은 연속 48프레임이 아니며 sliding window도 아니다. 공통 전처리의 구간 추출·Mel 계산을 활용했으나 두 뷰 결합과 uint8 저장은 후속 실험에서 추가했다.

### WavLM: 발화 파형

Mel 대신 같은 발화의 파형을 사용한다. 학습 패키지는 중앙 최대 6초를 저장하고 epoch마다 그 안에서 임의의 최대 3초를 선택한다. 내부 dev와 공식 평가는 중앙 최대 3초다. 8kHz PCM16을 16kHz로 리샘플링하고 고정 48,000 샘플로 패딩하며 attention mask로 유효 길이를 전달한다. 리샘플링은 원음의 고주파 정보를 새로 복구하지 않는다.

학습의 무작위 구간 선택은 증강이다. 실제 추론과 공식 평가는 같은 중앙 구간 규칙을 사용한다. 클래스별로 다른 전처리를 적용하지 않는다.

## 3. 모델 선택의 근거와 구조

### ResNet: 작은 시간·주파수 패턴을 학습하는 기준 모델

log-Mel은 2차원 배열이므로 2D CNN으로 주변 음향 패턴을 학습할 수 있다. 작은 입력을 초기에 급격히 줄이지 않도록 stem을 3×3/stride 1로 바꾸고 초기 max-pooling을 제거했다. 음성을 이미지로 인식하는 과제가 아니라, 음향 표현을 CNN으로 분류하는 접근이다.

동일 Mel을 3채널로 반복한 후 ImageNet 정규화, small-stem, 네 residual stage, global average pooling, dropout, 2출력 linear와 softmax를 사용한다. ResNet18/34의 block 수는 각각 `[2,2,2,2]`, `[3,4,6,3]`이다. ImageNet 초기화 후 음성으로 학습했으며 사전학습 자체의 효과를 별도 통제 실험으로 입증하지는 않았다.

### WavLM: 다른 음성 표현이 기존 오류를 보완할 수 있다는 가설

WavLM 원 논문의 V-B3·V-E5와 그림 2·3은 화자 관련 과제에서 저층 표현의 기여를 분석한다. 이를 근거로 **화자 관련 음향 정보를 활용하는 표현이 역할 분류에도 도움이 될 수 있다**는 가설을 세웠다. [WavLM 원 논문](https://arxiv.org/html/2110.13900v5)

단, 화자 신원과 대원/신고자 역할은 다른 목표다. '0~4층에 위급 정보가 집중된다', '4층이 이 과제의 최적 층이다'는 결론은 문헌이나 이번 실험으로 입증하지 않았다. 모델이 어조·음색·긴급성을 직접 사용했는지도 측정하지 않았다. 낮은 층에도 내용 정보가 있을 수 있다.

12개 Transformer 중 앞 4개 블록만 실행한다. 코드 인덱스는 0~3, 출력은 hidden state 4에 해당한다. hidden state 0은 첫 Transformer 이전 표현이다. **0~4층 출력을 모두 합친 모델은 아니다.** 4개 선택에는 제한된 GPU 자원과 초기 4층 임베딩 실험도 고려했으나 동일 조건의 4/8/12층 미세조정 비교는 수행하지 않았다.

- CNN encoder와 첫 4개 Transformer 블록의 마지막 출력을 사용한다.
- attention으로 프레임 가중치를 구해 가중 평균·표준편차를 결합한다.
- LayerNorm, Linear(1536→256), GELU, dropout 0.2, Linear(256→1), sigmoid로 신고자 확률을 만든다.
- 초기 헤드 학습 후 Transformer 블록 3·4와 헤드를 미세조정한다. CNN과 블록 1·2는 고정한다.
- 10만 발화, batch 16, 조기 종료 OFF, 6 epoch 실험 중 내부 dev Accuracy@0.5 최고인 epoch 5/step 30,000 모델을 선택했다.

초기 고정 임베딩+LightGBM/로지스틱 회귀와 현재 미세조정 WavLM은 다른 실험이다. 초기 검증 2,000개 점수를 전체 Validation과 섞지 않는다.

## 4. 실험으로 확인한 내용

아래는 동일한 공식 Validation 111,947개, 최종 threshold 0.5 기준이다. 학습량·전처리가 다르므로 구조 자체의 공정한 우열 비교는 아니다.

| 모델 | Accuracy | 대원 Recall | 신고자 Recall |
|---|---:|---:|---:|
| ResNet18 | 91.106% | 86.85% | 95.05% |
| ResNet34 | 91.030% | 86.29% | 95.42% |
| WavLM 4층 미세조정 | 90.426% | 89.59% | 91.20% |
| ResNet18+34, 50:50 | 91.419% | 86.92% | 95.59% |
| ResNet18/34/WavLM, 37.5:37.5:25 | 91.819% | 87.540% | 95.785% |
| **ResNet18/34/WavLM, 30:30:40** | **91.972%** | **87.990%** | **95.663%** |

WavLM 단독은 전체 정확도가 더 낮지만 대원 Recall은 더 높다. 동일 ID로 맞춰 보니 ResNet18+34가 틀리고 WavLM이 맞힌 발화가 3,573개였다. 반대로 ResNet 결합이 맞히고 WavLM이 틀린 발화도 4,685개이므로 단순 교체는 손해였다. 둘 다 틀린 발화는 6,033개였다.

따라서 단독 점수뿐 아니라 서로 다른 오류를 기준으로 확률 결합을 검토했다. WavLM 비중 15~60%의 후보를 순차 비교한 결과 40%가 비교 범위 내 최고였다. 45%보다 정답이 20개 많았지만 이 작은 차이의 일반화를 보장하지 않는다.

**확인한 결론:** 이번 Validation에서는 서로 다른 입력 표현과 학습 방식의 결합이 전체 정확도를 개선했다. **미확인:** 긴급성·어조를 직접 포착해 개선됐다는 인과 설명, 새 화자·환경의 일반화, 4층의 최적성.

## 5. 최고 모델의 결합 규칙

```python
p_caller = 0.30 * p_resnet18 + 0.30 * p_resnet34 + 0.40 * p_wavlm4
speaker = 1 if p_caller >= 0.5 else 0
```

학습 파라미터 평균이 아니라 동일 발화의 신고자 확률을 가중 평균한다. 세 가중치와 서로 다른 두 전처리가 모두 필요하다. 임계값을 이동하거나 클래스별 임계값을 설정하지 않는다.

결합 계산에는 팀원이 내보낸 WavLM 소수점 6자리 CSV 확률과 ResNet 예측 캐시를 사용했다. 실제 WavLM 가중치를 통합 추론에 로드해 full precision 기준으로 재평가해야 한다. 기존 단일 모델 inference.py만으로 이 점수가 재현되는 것은 아니다.

## 6. 한계와 규정 확인

- 같은 Validation을 여러 실험과 비율 선택에 사용했다. 독립 Test로 설명하지 않는다.
- ResNet 체크포인트는 과거 튜닝 점수로 epoch를 선택한 이력이 있다. 현재 0.5 재평가가 그 이력을 없애지 않는다. 허용 여부와 재선택 필요성은 주최 측 확인 대상이다.
- 통화 단위 분리만으로 새 화자·다른 지역·통신 채널에서의 일반화를 보장할 수 없다. 장비·채널 단서에 의존했을 가능성도 점검해야 한다.
- WavLM 단독 보고 시간은 RTX 5060 Laptop, batch 16에서 약 408.609초다. shard 읽기/리샘플/forward 범위이며 원본 WAV·JSON I/O는 제외한다. 세 모델 전체 추론시간으로 쓰지 않는다. 총 파라미터는 70,617,942개이며 fine-tuning 대상 합계는 47,120,046개다. 학습 대상 파라미터와 추론 Active 파라미터는 같은 개념이 아니며, end-to-end 시간은 별도 측정 대상이다.
- 30만 발화 WavLM은 데이터·코드만 준비했으며 GPU 학습 결과는 없다. 현재 점수는 기존 10만 발화 WavLM 조합이다. 94% 달성 기록은 아니다.
