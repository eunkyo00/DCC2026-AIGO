# Mission 2 — 신고자 / 119대원 발화 분류

## 1. Mission 2 한눈에 보기

통화에서 잘라낸 **한 사람의 한 발화**를 `speaker=0`(119대원) 또는 `speaker=1`(신고자)로 분류한다. 평가 지표는 **발화 단위 Accuracy**다. 클래스별 정답률은 실제 해당 클래스 중 맞힌 비율인 **Recall**로 별도 확인한다.

현재 보고된 최고 결과는 **Small-stem ResNet18과 ResNet34의 신고자 확률을 50:50으로 결합하고 임계값 0.52를 적용한 Validation Accuracy 91.437%**다. 단일 모델의 성능이나 비공개 Test 성능이 아니다.

```text
WAV + JSON의 startAt/endAt
    → 한 발화 구간 자르기
    → 앞 1.5초 log-Mel + 발화 전체 요약 log-Mel
    → [64,48] 특징
    → Small-stem ResNet18 / ResNet34
    → 신고자 확률 평균 → threshold 0.52 → speaker 0/1
```

`speaker`는 학습·평가 정답에만 사용한다. 전사 텍스트, 발화 순서, 파일명, 주소는 분류기 입력으로 사용하지 않는다. 경로와 발화 ID는 파일 찾기와 결과 매칭에만 사용한다.

> 문서 범위: 2026-10-02까지 공유된 실험 결과를 반영했다. 저장소의 `smallstem_resnet18/`와 그 결과 파일은 **초기 90.248957% 실험**의 기록이다. 후속 결과는 제공된 Colab 실행 로그와 클래스별 집계에 근거한다. 이번 변경은 README 갱신이며, 후속 체크포인트·예측 파일·코드 전체를 공개하거나 재검증한 것은 아니다.

## 2. 데이터와 전처리

### 2.1 데이터 구성

서울 지역 공통 검사·매니페스트 생성 파이프라인에서 확인한 수치다.

| 항목 | Training | 공식 Validation |
|---|---:|---:|
| WAV / JSON 매칭 통화 | 29,200 / 29,200 | 3,640 / 3,640 |
| 발화 | 889,358 | 111,947 |
| 119대원 (`speaker=0`) | 427,161 | 53,845 |
| 신고자 (`speaker=1`) | 462,197 | 58,102 |

검사한 WAV는 **8kHz, mono, 16-bit PCM**이었다. 사용한 데이터 복사본의 검사에서 WAV/JSON 누락·손상 0건을 기록했다. 상세 집계는 [EDA 보고서](eda/REPORT.md)를 참고한다. 공식 Training/Validation 분리를 유지하며, 같은 통화의 발화를 임의로 양쪽에 나눠 넣지 않는다. 다만 동일 인물이 서로 다른 통화로 두 split에 존재하는지는 확인하지 못했다.

### 2.2 현재 주력 전처리: `first_plus_whole`

**한 발화의 앞 1.5초와 발화 전체의 요약을 함께 사용한다.** 전체 통화가 아니라 `startAt`·`endAt`으로 자른 해당 발화만 처리한다.

1. **발화 자르기**: JSON의 시작·종료 시각(ms)에 해당하는 WAV 구간을 가져온다.
2. **앞부분 특징**: 앞 1.5초를 사용한다. 더 짧으면 뒤에 0을 채우는 zero-padding을 적용한다. 64개 Mel 주파수 대역의 log-Mel 특징 `[64,24]`를 만든다.
3. **전체 발화 특징**: 1.5초보다 긴 발화는 전체 구간의 log-Mel을 만든 뒤, 시간축을 24개 구간으로 나눠 각 구간의 특징을 평균한다. 결과는 `[64,24]`다. 1.5초 이하이면 앞부분 특징을 그대로 재사용한다.
4. **결합**: 두 특징을 시간축 방향으로 붙여 `[64,48]`로 만든다. 앞 24프레임과 뒤 24프레임은 서로 다른 시간 범위다. **48프레임이 일정한 시간 간격으로 연속된 음성은 아니다.**
5. **정규화·저장**: log-Mel을 `clip((mel + 80) / 80, 0, 1)`로 변환한다. 전체 발화 평균도 이 정규화된 특징에 적용한다. 최종 특징은 `round(feature * 255)`로 `uint8` 저장하고, 학습 시 float32로 읽어 255로 나눈다.

예를 들어 4초 발화는 **앞 1.5초 특징 + 4초 전체의 압축된 특징**으로 표현한다. 뒤쪽 음성을 완전히 버리지는 않지만, 시간축 평균으로 압축하면서 세부적인 변화는 손실될 수 있다.

로그 멜 스펙트로그램은 시간에 따른 주파수 대역별 에너지 분포이며, 음성을 글자로 변환한 것이 아니다. 특징을 미리 계산한 이유는 원본 WAV 전체를 Colab에 올리지 않고 학습하기 위해서다. 현재 특징 파일은 `mission02_features_full.zip`이며, 새로운 음성 추론에는 동일한 전처리가 필요하다.

### 2.3 전처리 실험 구분

| 이름 | 특징 | 사용 범위 |
|---|---|---|
| `first_1p5` | 앞 1.5초만, `[64,24]`, float16 | 초기 90.25% 실험 |
| **`first_plus_whole`** | 앞 1.5초 + 전체 발화 요약, `[64,48]`, uint8 | 현재 최고 모델 및 대원 가중치 실험 |
| `three_window` | 앞·중간·끝에서 1.5초씩 선택, 각각 16프레임으로 요약·결합 | 별도 비교 실험; 현재 최고 모델에는 미사용 |

현재 방식은 **sliding window가 아니다**. 일정 간격으로 창을 계속 이동시키지 않는다. 공통 검사·구간 자르기·Mel 추출 함수를 활용했지만, 두 뷰 결합과 uint8 저장은 Mission 2 후속 실험에서 추가했다. 모든 후속 전처리가 공통 GitHub 명령 그대로였다고 설명하지 않는다.

## 3. 왜 이미지 분류에 쓰이는 ResNet을 선택했는가?

ResNet을 사용해도 작업 자체는 **음성 분류**다. 음성을 시간×주파수의 2차원 특징으로 표현하고 CNN으로 분류한 것이다.

- log-Mel의 국소적인 시간·주파수 패턴을 2차원 합성곱으로 학습할 수 있다.
- ResNet의 잔차 연결은 깊은 신경망의 학습을 돕는다.
- ImageNet 사전학습 가중치를 초기값으로 활용한 뒤 음성 데이터로 전체 모델을 학습한다. 사전학습의 효과 자체를 따로 입증한 실험은 아니다.
- 작은 Mel 입력을 초기에 과도하게 축소하지 않도록 **small-stem** 구조를 적용했다.

정확한 설명은 **“전처리를 ResNet 입력에 맞춰 설계했고 실험에서 유효한 결과를 얻었다”**이다. “음성 전용 모델보다 이미지 모델이 본질적으로 우수하다”는 결론은 내리지 않는다.

### WavLM과 비교할 때의 주의점

WavLM에는 동일한 Mel 특징을 넣지 않았다. 발화의 앞 최대 3초 파형을 8kHz에서 16kHz로 리샘플링하고, 고정된 WavLM hidden state의 평균·표준편차 임베딩을 추출했다. 4·8·12층과 LightGBM/로지스틱 회귀를 비교했으며 **WavLM 자체는 미세조정하지 않았다**.

| 조건 | 주력 ResNet | WavLM 예비 실험 |
|---|---|---|
| 입력 | 앞 1.5초 + 전체 발화 요약 Mel | 앞 최대 3초 파형 |
| 학습 발화 수 | 889,358 | 10,000 → 50,000 |
| 학습 대상 | ResNet 전체 | 고정 임베딩 위의 분류기만 |
| 검증 | 전체 111,947개 | 그중 동일한 2,000개 표본 |

따라서 WavLM 예비 결과가 낮았다고 해서 ResNet이 모델 구조상 더 적합하다고 확정할 수 없다. 다른 실험자의 WavLM 결과와 비교하려면 학습량, 입력 길이, 사용 층, 분류기, fine-tuning 여부, split을 확인해야 한다. 현재 ResNet을 선택한 이유는 **확보한 전체 검증 성능과 실행 가능한 파이프라인**에 근거한다.

## 4. 모델 구조와 학습

### 4.1 Small-stem ResNet18 / ResNet34

```text
[B,1,64,48] log-Mel
    → 같은 Mel을 3채널로 반복 + ImageNet 채널별 정규화
    → 3×3 convolution, stride 1 + BatchNorm + ReLU
    → 초기 max-pooling 생략
    → 4개 residual stage
    → global average pooling
    → Dropout + Linear(512 → 2)
    → softmax: 대원/신고자 확률
```

3채널 반복은 새 음성 정보를 만드는 것이 아니라 backbone 입력 형식에 맞추는 처리다. ResNet18의 residual block 수는 `[2,2,2,2]`, ResNet34는 `[3,4,6,3]`이다. 일반 ResNet의 `7×7, stride=2` stem 대신 `3×3, stride=1`을 사용하고 초기 max-pooling을 제거했다. ImageNet 초기화 시 기존 7×7 stem 가중치를 3×3으로 축소해 사용한다.

AdamW, cosine 학습률 조절, early stopping을 사용하고 실험에 따라 SpecAugment, Mixup, label smoothing을 적용했다. Validation은 역전파가 아니라 epoch·임계값·모델 선택에 사용한다. 초기 90.25%의 상세 설정은 [기존 실험 문서](smallstem_resnet18/README.md)에 보존되어 있으며 후속 설정과 혼동하지 않는다.

### 4.2 현재 최고 결합 모델

동일한 `first_plus_whole` 특징을 두 모델에 입력하고 **신고자 확률**을 평균한다.

```python
p_caller = 0.5 * p_resnet18 + 0.5 * p_resnet34
speaker = 1 if p_caller >= 0.52 else 0
```

모델 가중치 평균이 아니므로 추론에 두 모델이 모두 필요하다. 단독 ResNet18의 임계값은 0.515, ResNet34는 0.525였지만 결합에서는 확률 평균 후 **0.52를 한 번 적용**한다.

초기 90.248957%는 제공된 체크포인트와 [학습 기록](smallstem_resnet18/results/history.json)을 대조했다. 후속 수치는 공유된 Colab 평가 출력 기준이다. 여러 학습 조건이 함께 달라졌으므로 상승분 전체를 특정 전처리의 효과로 단정하지 않는다. 이전 요약의 91.116% 대신, 전체 재평가에서 나온 단독 ResNet18 **91.113652%**를 기준으로 사용한다.

## 6. 결과 해석과 진행 중인 개선

- **깊은 모델만으로 해결되지 않았다.** ResNet34 단독은 기존 ResNet18을 넘지 못했지만 확률 결합은 일부 오답을 보완했다.
- **임계값 조정의 개선은 작았다.** threshold 0.50 → 0.52는 약 0.018%p 상승이었다. 임계값을 높이면 대원 Recall이 늘 수 있지만 신고자 Recall과 전체 Accuracy가 내려갈 수 있다.
- **93%는 아직 달성하지 않았다.** 현재 102,361개 정답에서 전체 93% 이상이 되려면 최소 1,750개를 더 맞혀야 한다. 신고자 정답 수가 그대로라면 대원 Recall 약 90.74%가 필요하다.
- **시간축 압축의 한계가 있다.** 전체 발화도 24프레임으로 평균 요약하므로 세부 정보가 모두 보존되지는 않는다.
- **Validation 선택 편향이 있다.** 동일 Validation에서 여러 구조·epoch·threshold·결합을 선택했다. 보고 수치는 독립 Test 성능이나 제출 완료 증명이 아니다.

후속으로 두 뷰를 별도 인코딩하는 Dual-view ResNet을 준비했으나 여기에서 확정 성능을 보고하지 않는다. 현재 대원 오분류 개선 실험은 Training 손실 가중치 `[1.0,1.0]`과 `[1.2,1.0]`을 비교한다. 같은 초기 모델과 설정의 대조군을 두고 **대원 Recall·전체 Accuracy·신고자 Recall**을 함께 확인한다. Validation에는 가중 학습이나 역전파를 적용하지 않는다. 결과 미확인 실험을 성능 개선으로 기재하지 않는다.
