# Mission 2: 신고자와 119대원 발화 분류

## 5장 구성 개요

1. 문제 정의와 데이터 분석: 사용할 수 있는 정보와 데이터 특성을 확인
2. 전처리 설계: 앞 1.5초와 발화 전체의 정보를 고정 크기로 표현
3. 모델 설계: 작은 음향 특징에 맞춘 Small-stem ResNet 구성
4. 실험 과정: 구조 변경, 전체 발화 활용, 미세조정, WavLM 비교, 확률 결합, 손실 가중치 실험
5. 결과 해석: 전체 성능과 클래스별 오류를 분석하고 사회안전 활용 가능성 검토

아래는 각 장에 활용할 상세 원고다. 실험 수치는 전체 Validation 평가, 소규모 표본 평가, 과거 임계값 튜닝 결과를 구분해 표기했다.

## 1장. 문제 정의와 데이터 분석

- 목표: 한 사람의 한 발화 음성을 119대원(`speaker=0`)과 신고자(`speaker=1`)로 분류
- JSON의 `startAt`, `endAt`으로 해당 발화 구간을 추출하고, 전사 텍스트와 발화 순서는 모델 입력에서 제외
- WAV·JSON 매칭, 음성 형식, 발화 길이와 클래스 분포를 점검
- 서울 Training 데이터로 학습하고 공식 Validation 분리를 유지
- 발화마다 길이가 달라 고정 크기의 입력이 필요하며, 한 발화 내부의 음향적 패턴을 학습하도록 설계

| 구분         | Training | Validation |
| ------------ | -------: | ---------: |
| 통화 수      |   29,200 |      3,640 |
| 발화 수      |  889,358 |    111,947 |
| 119대원 발화 |  427,161 |     53,845 |
| 신고자 발화  |  462,197 |     58,102 |

음성 형식: 8kHz, mono, 16-bit PCM. 검사한 데이터 복사본에서 WAV·JSON 누락 및 손상 0건.

### 문제를 어떻게 정의했는가

이 과제는 통화 전체에서 사람의 신원을 찾는 것이 아니라, 이미 시작과 끝이 지정된 발화 하나의 역할을 분류하는 문제다. 모델은 해당 발화의 음성만 보고 대원과 신고자를 구분해야 한다. 따라서 “119입니다”와 같은 전사 텍스트, 발화 순서, 앞뒤 대화 내용에 의존하지 않도록 입력 범위를 제한했다. `speaker`는 학습과 평가의 정답으로만 사용하고, 파일 경로와 발화 ID는 음원 조회 및 결과 매칭에 사용했다.

### 데이터 점검에서 설계로 연결한 내용

먼저 WAV와 JSON이 짝을 이루는지, 음성 파일이 정상적으로 읽히는지, 샘플레이트와 채널 수가 일관적인지 확인했다. 이후 JSON의 발화 구간을 기준으로 매니페스트를 만들고 발화 길이와 클래스 분포를 분석했다. 통화 수와 모델 학습 표본 수는 다르며, 하나의 통화에서 여러 발화가 만들어진다.

대원과 신고자는 두 split 모두에서 비슷한 규모로 존재한다. 다만 클래스 수가 비슷하더라도 각 클래스의 분류 난도가 같다고 볼 수는 없으므로, 전체 Accuracy와 함께 클래스별 Recall을 확인했다. 공식 Training과 Validation을 유지하고 같은 통화의 발화를 임의로 두 split에 나누지 않았다. 동일 인물이 서로 다른 통화로 양쪽에 포함되는지는 확인하지 못했다.

발화 길이가 다양하다는 점은 전처리 설계의 출발점이었다. 짧은 발화에는 padding이 필요하고, 긴 발화를 일정 길이로 자르면 뒷부분 정보가 제외된다. 이후 실험에서는 입력 크기를 일정하게 유지하면서 긴 발화의 정보를 더 반영하는 방법을 검토했다.

## 2장. 앞부분과 전체 발화를 함께 사용하는 전처리

- 음성을 시간·주파수별 에너지 분포인 **log-Mel 스펙트로그램**으로 변환
- 앞 1.5초는 비교적 세밀한 패턴을 담는 고정 길이 특징 `[64,24]`로 표현하며, 짧은 발화는 뒤에 0을 채움
- 1.5초보다 긴 발화는 해당 발화 전체의 시간축을 24개 구간으로 나누어 평균 요약하고, 짧은 발화는 앞부분 특징을 재사용
- 두 특징을 결합해 **`[64,48]` 입력**을 구성하고 모든 클래스와 데이터 분할에 같은 전처리를 적용
- 앞 1.5초만 사용할 때 제외되는 뒤쪽 음성도 반영하되, 평균 요약 과정에서 세부적인 시간 변화는 손실될 수 있음

**처리 흐름:** 발화 구간 추출 → 앞 1.5초 log-Mel + 전체 발화 요약 log-Mel → 특징 결합 → 정규화·uint8 저장 → 학습 시 float32 복원

주석: Sliding window 방식이 아니며, 결합한 48프레임은 일정한 간격의 연속 음성이 아니다. 특징 사전 계산은 Colab 전송 용량과 반복 전처리 부담을 줄이기 위한 선택이다.

### 초기 전처리에서 발견한 한계

초기 `first_1p5` 방식은 발화의 앞 1.5초만 사용해 `[64,24]` log-Mel 특징을 만들었다. 입력 크기를 통일하고 계산량을 줄일 수 있지만, 1.5초보다 긴 발화의 뒷부분은 활용하지 못했다. 기존 전처리 진단에서 Validation 발화 111,947개 중 53,496개, 약 47.79%가 이 조건에 해당했다.

따라서 앞부분의 비교적 세밀한 패턴을 유지하면서 해당 발화 전체의 정보를 추가하는 `first_plus_whole`을 설계했다. 여기서 “전체”는 통화 전체가 아니라 JSON의 `startAt`과 `endAt`으로 자른 한 발화 전체를 의미한다.

### 현재 전처리의 세부 과정

1. **발화 추출:** JSON의 시작·종료 시각(ms)을 음성 샘플 위치로 변환해 해당 구간을 자른다.
2. **앞부분 표현:** 앞 1.5초를 사용하고, 짧으면 뒤에 0을 채운다. 이를 64개 Mel 대역과 24개 시간 프레임으로 표현한다.
3. **전체 구간 표현:** 긴 발화의 전체 log-Mel을 계산하고 시간축을 24개 구간으로 나누어 평균한다. 1.5초 이하이면 앞부분 특징을 재사용한다.
4. **정규화와 결합:** log-Mel에 `clip((mel + 80) / 80, 0, 1)`을 적용한다. 전체 구간 평균도 정규화된 특징에서 계산하며, 두 `[64,24]` 특징을 붙여 `[64,48]`로 만든다.
5. **저장과 복원:** `round(feature * 255)`로 uint8 특징을 저장하고, 학습·추론에서는 float32로 변환해 255로 나눈다. 새 음성도 동일한 양자화와 복원 과정을 거친다.

예를 들어 4초 발화는 “앞 1.5초의 특징”과 “4초 전체를 24프레임으로 요약한 특징”으로 표현한다. 뒤쪽 음성의 에너지도 반영할 수 있지만, 전체 요약은 시간축을 압축하므로 빠른 변화나 짧은 사건의 세부 정보가 약해질 수 있다.

### 저장 방식과 학습 효율

원본 WAV를 Mac에서 읽어 특징을 미리 생성하고, 특징 파일을 Colab으로 옮겨 반복 학습했다. 초기 `[64,24]` float16 특징과 현재 `[64,48]` uint8 특징은 원소 수와 원소당 저장 크기가 반대로 변하므로 표본당 배열 저장 용량이 같다. 실제 학습 입력은 float32로 복원하며, SpecAugment와 Mixup은 실험 설정에 따라 학습 중 적용했다.

공통 파이프라인의 발화 추출·Mel 계산 구현을 활용했지만, 두 표현의 결합과 uint8 저장은 후속 실험에서 추가한 처리다. 전처리를 변경할 때에는 학습과 추론 양쪽에 같은 처리를 적용했다.

## 3장. ResNet 선택 이유와 음성 입력에 맞춘 구조

- log-Mel은 시간과 주파수의 2차원 배열이므로 CNN으로 주변의 시간·주파수 패턴을 학습할 수 있음
- ResNet의 잔차 연결을 활용하고 ImageNet 사전학습 가중치로 초기화한 뒤 음성 데이터로 전체 모델을 학습
- 작은 Mel 입력의 초기 해상도 손실을 줄이기 위해 **Small-stem** 적용: 첫 합성곱을 `3×3, stride 1`로 변경하고 초기 max-pooling 제거
- 특징 추출 후 119대원과 신고자의 확률을 출력

**모델 흐름:** `[1,64,48]` log-Mel → 3채널 반복·정규화 → Small-stem → 4개 residual stage → Global Average Pooling → Dropout·Linear → 두 클래스 확률

주석: 3채널 반복은 같은 특징을 복제한 입력 형식 변환이다. 음색·발성 변화와 관련될 수 있는 음향 패턴을 학습하도록 설계했으며, 특정 음색이나 어조를 실제로 학습했는지는 직접 검증하지 않았다.

### 왜 ResNet을 사용했는가

log-Mel은 시간에 따라 주파수 대역별 에너지가 어떻게 변하는지 나타낸다. 2차원 합성곱은 이 배열의 가까운 시간·주파수 위치를 함께 처리할 수 있어 음향 패턴을 분류하는 방법으로 사용할 수 있다. ResNet의 잔차 연결은 입력 정보를 다음 층으로 전달하는 경로를 제공해 깊은 네트워크의 학습을 돕는다.

ImageNet 사전학습 가중치를 초기값으로 활용한 뒤 음성 데이터로 모델 전체를 학습했다. 음향 특징을 3채널로 반복하는 것은 기존 backbone의 입력 형식에 맞추기 위한 과정이다. 이 실험만으로 이미지 사전학습 자체의 효과를 분리해 입증한 것은 아니다.

### Small-stem으로 변경한 이유

일반적인 ResNet은 첫 합성곱에서 `7×7, stride 2`를 사용하고 이어서 max-pooling으로 해상도를 줄인다. 입력이 작은 Mel 특징에서는 초반부터 시간축과 주파수축 정보가 빠르게 압축될 수 있다. 이를 줄이기 위해 첫 합성곱을 `3×3, stride 1`로 바꾸고 초기 max-pooling을 제거했다. ImageNet 초기화 시 기존 7×7 stem 가중치를 3×3으로 축소해 사용했다.

이후 네 개의 residual stage로 특징을 추출한다. ResNet18의 block 수는 `[2,2,2,2]`, ResNet34는 `[3,4,6,3]`이다. 마지막에는 Global Average Pooling, Dropout, 2개 출력의 Linear 층을 사용하고 softmax로 대원·신고자 확률을 계산한다.

### 학습과 모델 선택

AdamW와 cosine 학습률 조절, early stopping을 사용하고 실험에 따라 SpecAugment, Mixup, label smoothing을 적용했다. 이 설정들은 모든 실험에서 동일하지 않으며, 추가 미세조정에서는 증강을 줄이거나 제거하는 조건도 비교했다. Validation은 평가와 모델 선택에 사용하고 역전파에는 포함하지 않았다.

현재 판정 임계값은 0.5로 고정한다. 과거 실험에는 임계값 탐색으로 선택한 체크포인트가 있으므로, 해당 이력과 현재 0.5를 적용해 재평가한 성능을 구분한다.

## 4장. 실험을 통해 결정한 모델 구성

| 실험                          | 확인한 내용과 판단                                           |
| ----------------------------- | ------------------------------------------------------------ |
| ResNet18 단독                 | 전체 Validation Accuracy 91.106%                             |
| ResNet34 단독                 | 91.030%로, 깊이 증가만으로 기존 모델을 넘지 못함             |
| ResNet18 + ResNet34 확률 결합 | 91.419%로 단독 모델보다 높아 현재 구성으로 유지              |
| 119대원 손실 가중치 증가      | 대원 Recall은 상승했지만 신고자 오류가 늘어 전체 정답이 감소하므로 채택하지 않음 |
| WavLM 고정 임베딩 분류        | 예비 실험으로 검토했으며 학습량·입력·학습 방식이 달라 모델 구조의 우열 판단은 보류 |

**현재 구성:** 두 Small-stem ResNet의 신고자 확률을 50:50으로 평균하고, **0.5 이상이면 신고자, 미만이면 119대원**으로 분류한다.

주석: ResNet 단독·결합 수치는 전체 Validation 111,947개와 임계값 0.5 기준이다. WavLM은 최대 50,000개 학습 발화의 고정 임베딩 위에서 분류기만 학습하고 검증 2,000개 표본으로 평가했다. 전체 Training으로 학습한 ResNet과 공정한 구조 비교 실험은 아니다.

### 실험 1. 초기 ResNet과 입력 구조 개선

초기에는 앞 1.5초 log-Mel 특징으로 일반 ResNet18을 학습했다. 이후 작은 Mel 입력을 초기에 덜 축소하도록 Small-stem ResNet18을 적용하고, 시간축 특징을 추가로 처리하는 TDNN과 Small-stem ResNet을 결합한 hybrid 모델도 비교했다.

당시 공유된 결과는 일반 ResNet18 약 88.59%, Small-stem ResNet18 약 90.25%, hybrid 약 90.00%였다. 이 단계에서는 Small-stem ResNet18이 가장 높아 후속 실험의 기반으로 사용했다. **이 값들은 과거 평가 설정의 실험 기록이며, 현재 고정 임계값 0.5 기준 비교표와 직접 혼합하지 않는다.** 초기 Small-stem 모델의 0.5 판정 결과는 90.139977%다.

### 실험 2. 발화 전체 정보 추가와 후속 미세조정

앞 1.5초만 사용하는 방식의 정보 손실을 줄이기 위해 `first_plus_whole` 특징으로 Small-stem ResNet18을 학습했다. 전체 발화 특징을 추가한 초기 길이별 진단에서는 약 90.8573%가 보고되었고, 이후 낮은 학습률의 미세조정 등 후속 실험을 진행했다. 현재 비교에 사용하는 단독 ResNet18 체크포인트는 임계값 0.5에서 **91.105612%**를 기록했다.

특징 표현, 양자화, 재학습 및 미세조정 조건이 함께 달라졌으므로 성능 증가 전체를 “발화 전체 정보를 넣은 효과”로 단정할 수는 없다. 다만 이 실험 과정을 통해 전체 발화 요약을 포함한 입력과 후속 학습 설정을 현재 모델 구성으로 채택했다.

앞·중간·끝의 1.5초 구간을 각각 요약하는 `three_window` 전처리도 별도 비교 대상으로 준비했다. 현재 정리된 기록만으로 해당 방식의 최종 성능을 확정할 수 없으므로, 최종 채택 근거에는 포함하지 않는다.

### 실험 3. WavLM 기반 음성 표현과 비교

음성 사전학습 모델의 표현이 화자 역할 구분에 도움이 되는지 확인하기 위해 WavLM 실험을 진행했다. 동일한 원천 음성 데이터에서 JSON으로 발화 구간을 추출하되, ResNet과 WavLM의 입력 형식에 맞추어 전처리했다.

| 비교 항목             | ResNet                            | WavLM 예비 실험                                       |
| --------------------- | --------------------------------- | ----------------------------------------------------- |
| 모델 입력             | 앞 1.5초 + 전체 발화 요약 log-Mel | 발화 앞 최대 3초 파형                                 |
| 음성 처리             | 8kHz 음성에서 Mel 특징 계산       | 8kHz 파형을 16kHz로 리샘플링                          |
| 특징 학습             | ResNet 전체를 음성 데이터로 학습  | WavLM을 고정하고 hidden state 추출                    |
| 분류 방법             | ResNet의 분류 층                  | 평균·표준편차 임베딩 위의 LightGBM 또는 로지스틱 회귀 |
| 학습 발화 수          | 889,358                           | 10,000 및 50,000                                      |
| 직접 비교한 검증 표본 | 동일한 2,000개                    | 동일한 2,000개                                        |

WavLM의 4·8·12층 표현과 분류기를 비교했다. 아래는 공유된 대표 결과다.

| 방법                                     |            학습 발화 수 | 동일 검증 2,000개 Accuracy |
| ---------------------------------------- | ----------------------: | -------------------------: |
| WavLM 4층 + LightGBM                     |                  10,000 |                     84.30% |
| WavLM 4층 + 로지스틱 회귀                |                  10,000 |                     85.60% |
| WavLM 4층 + 로지스틱 회귀                |                  50,000 |                     87.50% |
| 기존 ResNet18 단독, 임계값 0.5           |                 889,358 |                     91.90% |
| ResNet18 75% + 50k WavLM 25%, 임계값 0.5 | 각 모델의 학습량이 다름 |                     92.25% |

**수행한 실험 조건에서는 ResNet이 WavLM 임베딩 기반 분류보다 높은 정확도를 보였다.** 같은 검증 표본에서 ResNet 단독은 91.90%, 50,000개 발화로 학습한 WavLM 임베딩 분류기는 87.50%였다. 이에 현재 확보한 성능과 실행 환경을 기준으로 ResNet을 주력 모델로 유지했다.

WavLM과의 확률 결합도 확인했으며, 2,000개 표본에서는 91.90%에서 92.25%로 정답이 7개 증가했다. 다만 소규모 검증 표본의 탐색 결과이므로 전체 Validation에서 확인한 ResNet18+34 결합 모델을 대체할 근거로 사용하지 않았다.

주석: 두 방법은 원천 데이터와 발화 추출 기준을 공유하지만 **동일한 전처리 특징을 사용한 실험은 아니다.** 입력 길이, 학습량, 모델 미세조정 여부도 달라 이 결과를 모델 구조 자체의 일반적인 우열로 해석하지 않는다.

### 실험 4. 추가 미세조정, ResNet34, 두 모델의 확률 결합

기존 ResNet18에서 증강 없는 저학습률 미세조정을 시도하고, 더 깊은 Small-stem ResNet34도 학습했다. 동일한 `first_plus_whole` 특징을 사용해 전체 Validation에서 임계값 0.5로 평가했다.

| 모델                                 | 전체 Validation Accuracy@0.5 |
| ------------------------------------ | ---------------------------: |
| 기존 ResNet18                        |                   91.105612% |
| 증강 없는 추가 미세조정 ResNet18     |                   91.043976% |
| ResNet34                             |                   91.029684% |
| 기존 ResNet18 + ResNet34, 확률 50:50 |               **91.419154%** |

추가 미세조정과 ResNet34 단독은 기존 ResNet18을 넘지 못했다. 반면 기존 ResNet18과 ResNet34의 신고자 확률을 평균하면 정확도가 약 0.314%p 높아졌다. 단독 정확도가 더 낮은 모델도 다른 모델과 결합했을 때 일부 오류를 보완할 수 있음을 관찰했다.

최종 결합은 모델의 파라미터를 평균하는 방식이 아니다. 동일 발화를 두 모델에 각각 입력하고, 두 신고자 확률을 평균한 값으로 분류하므로 추론 시 두 모델의 가중치가 모두 필요하다.

`p_caller = 0.5 × p_ResNet18 + 0.5 × p_ResNet34`

`p_caller ≥ 0.5`이면 신고자, 그보다 작으면 119대원으로 판정한다.

### 실험 5. 대원 오류를 줄이기 위한 손실 가중치 비교

최고 결합 모델에서도 대원 Recall이 신고자 Recall보다 낮았다. 이에 Training에서 대원 오분류에 더 큰 손실을 부여하면 대원 분류가 개선되는지 확인했다. 같은 초기 ResNet18과 학습 설정에서 Cross-Entropy의 클래스 가중치만 `[1.0,1.0]`과 `[1.2,1.0]`으로 달리했다.

실험 설정은 seed 47, 최대 6 epoch, batch size 256, 학습률 `1e-5`, weight decay `1e-4`, dropout 0.25였다. 두 조건 모두 Mixup과 label smoothing을 사용하지 않고 기존 SpecAugment를 유지했다. Validation에는 가중 학습이나 역전파를 적용하지 않았다.

| 모델                  | 전체 Accuracy@0.5 | 대원 Recall | 신고자 Recall |
| --------------------- | ----------------: | ----------: | ------------: |
| 일반 학습 대조군      |           90.967% |      86.55% |        95.06% |
| 대원 손실 가중치 1.2  |           90.873% |      88.58% |        93.00% |
| 기존 ResNet18+34 결합 |       **91.419%** |      86.92% |        95.59% |

가중치 모델은 대조군보다 대원 발화를 1,093개 더 맞혔지만 신고자를 1,198개 더 틀려, 전체 정답이 105개 감소했다. 이번 설정에서는 대원 Recall 개선과 신고자 Recall 감소가 함께 나타났다. 가중치 모델을 포함한 시험 결합도 기존 91.419%를 넘지 못해 기존 ResNet18+34 결합을 유지했다.

입력의 앞부분과 전체 요약을 별도로 처리하는 Dual-view 구조도 추가 실험으로 준비했지만, 확정된 성능 기록이 없어 개선 결과나 최종 채택 모델에는 포함하지 않는다.

## 5장. 결과 해석과 사회안전 시사점

| 평가 지표                |                            결과 |
| ------------------------ | ------------------------------: |
| 전체 Validation Accuracy | **91.419%** (102,341 / 111,947) |
| 119대원 Recall           |    **86.92%** (46,804 / 53,845) |
| 신고자 Recall            |    **95.59%** (55,537 / 58,102) |

- 대원 발화를 신고자로 오인한 경우는 7,041개, 신고자 발화를 대원으로 오인한 경우는 2,565개로 오류 방향에 차이가 있음
- 전체 정확도와 함께 클래스별 Recall을 확인하고, 오답 음성의 발화 경계·중첩 발화 등을 분석해 원인을 검증할 필요가 있음
- 발화자 역할 분류는 신고 접수 대화의 역할별 기록과 후속 분석을 보조할 수 있음
- 오분류는 질문과 답변의 해석에 영향을 줄 수 있으므로 실제 현장 적용에는 오류 검토와 사람의 확인 절차가 필요함
- 새로운 화자와 녹음 환경에서 추가 검증이 필요하며, 현재 결과만으로 현장 성능을 보장할 수 없음

주석: 공식 Validation 결과이며 독립 Test 성능은 아니다. 기존 체크포인트에는 과거 임계값 튜닝 점수로 epoch를 선택한 이력이 있다. 제시한 수치는 최종 판정 임계값 0.5를 적용한 결과이며, 기존 선택 이력의 허용 여부 또는 고정 0.5 기준 재선택·재학습 필요 여부는 주최 측 확인이 필요하다.

### 전체 정확도와 오류 방향

전체 111,947개 발화 중 102,341개를 맞혔고 9,606개를 틀렸다. 클래스별 Recall은 실제 해당 클래스의 발화 중 올바르게 분류한 비율이다. 대원 Recall이 더 낮다는 것은 실제 대원 발화가 신고자로 잘못 분류되는 비율이 상대적으로 높다는 의미다.

| 실제 클래스 / 예측 클래스 | 119대원으로 예측 | 신고자로 예측 |
| ------------------------- | ---------------: | ------------: |
| 실제 119대원              |           46,804 |         7,041 |
| 실제 신고자               |            2,565 |        55,537 |

데이터의 클래스 수가 비슷함에도 오류는 대원 쪽에 더 많이 발생했다. 따라서 클래스 개수만 조정하기보다 어떤 발화에서 오류가 발생하는지 확인할 필요가 있다. 손실 가중치 실험은 특정 클래스의 Recall만 높이는 것이 전체 Accuracy 개선으로 이어지지는 않는다는 점을 보여준다.

### 길이별 분석에서 얻은 후속 점검 방향

과거 단독 ResNet18의 길이별 진단에서는 0.5~1.5초 발화가 상대적으로 약했다. 다만 0.5초 미만의 정확도가 더 높았으므로 “발화가 짧을수록 항상 어렵다”고 해석하지 않았다. 이 분석은 과거 임계값 0.515 기준으로, 현재 결합 모델의 임계값 0.5 성능과 구분해야 한다.

향후에는 현재 결합 모델의 오류를 길이별로 다시 집계하고, 실제 오답 음성을 들어 발화 경계의 정확성, 발화 중첩, 무음·잡음, 통화 환경 등의 영향을 확인할 수 있다. 이는 추가로 검증할 가설이며 현재 오류 원인으로 확정한 내용은 아니다. 검증 오답을 Training에 편입하지 않고 분석과 새로운 가설 수립에 활용한다.

### 사회안전 분야에서의 활용 가능성

신고 접수 음성에서 대원과 신고자의 발화를 구분하면 역할별 기록을 정리하고, 대원의 질문과 신고자의 응답을 후속 분석하는 작업을 보조할 수 있다. 본 실험은 그 과정의 기초가 되는 발화 역할 분류 가능성을 검토했다.

그러나 역할 오분류는 누가 질문하고 답했는지에 대한 해석을 바꿀 수 있다. 실제 적용을 위해서는 사람이 오류를 검토할 수 있는 절차가 필요하며, 다양한 지역·화자·녹음 환경을 포함한 별도 데이터로 성능을 확인해야 한다. 현재 서울 지역 공식 Validation 결과만으로 실제 현장의 일반화 성능을 보장할 수는 없다.

### 최종 결과의 범위

여러 구조와 학습 조건을 동일한 Validation에서 비교했으므로 모델 선택에 따른 편향이 있을 수 있다. 현재 수치는 공유된 평가 로그에 근거한 Validation 성능이며 독립 Test 결과나 최종 제출 완료를 의미하지 않는다. 두 모델을 사용하는 결합 추론의 실제 실행시간과 총 파라미터 수는 별도 측정이 필요하다. 앞서 설명한 가중치 실험의 batch size를 최종 결합 평가의 batch size로 대신 사용하지 않는다.
