# Mission 2 발표 원고: 음성 표현의 차이로 역할 분류 오류를 보완하기

7장 구성. '슬라이드 본문'은 PPT에, '발표 설명'은 발표자 노트에 사용한다. 수치는 주장을 뒷받침하는 근거로 배치한다. 마지막 7장은 사회안전 시사점만 한 페이지로 구성한다.

현재 최고 기록: **ResNet18 30% + ResNet34 30% + WavLM 4층 40%, threshold 0.5, 공식 Validation 91.972%**. 이하 수치는 공유 로그의 반올림 값이며 독립 Test 점수나 제출물 최종 검증 결과가 아니다.

## 1장. 음성만으로 구분해야 하는 신고자와 119대원

### 슬라이드 본문

- 한 발화의 음성만 듣고 대원과 신고자의 역할을 분류한다. 전사 텍스트와 대화 순서는 입력에서 제외한다.
- **문제 확인:** 기존 ResNet 결합은 신고자보다 대원 발화에서 더 자주 틀렸다.
- **연구 질문:** 모델을 더 깊게 만드는 것 외에, 다른 음성 표현으로 대원 오류를 보완할 수 있을까?

### 넣으면 좋은 표

| 기존 ResNet18+34의 결과 | 해석 |
|---|---|
| 대원 Recall 86.92% | 실제 대원을 신고자로 혼동하는 오류가 상대적으로 많음 |
| 신고자 Recall 95.59% | 두 역할의 오류 방향과 분류 난도가 같지 않음 |

각주: 공식 Validation 111,947발화, threshold 0.5. Recall은 실제 해당 역할 중 맞힌 비율.

### 발표 설명

“목표는 특정 사람의 신원을 찾는 것이 아니라 발화자의 역할을 구분하는 것입니다. 전체 정확도만 보면 약 91%였지만, 역할별로 나누면 대원 오류가 더 컸습니다. 그래서 단독 점수가 높은 모델만 찾기보다 기존 모델이 놓치는 단서를 보완하는 방향으로 실험했습니다.”

대원 Recall이 낮다는 사실은 확인했다. 짧은 응답·잡음·채널 중 무엇이 원인인지는 직접 분석 없이 단정하지 않는다. '대원은 항상 침착하고 신고자는 항상 흥분한다'는 고정관념을 분류 규칙으로 쓰지 않는다.

## 2장. 입력 설계: 앞부분의 세부 패턴과 발화 전체의 경향

### 슬라이드 본문

- **문제:** 앞 1.5초만 쓰면 긴 발화의 뒷부분이 빠진다. 원본 전체의 반복 처리는 저장·계산 부담도 크다.
- **가설:** 앞부분의 세부 패턴에 전체 발화 요약을 더하면 작은 입력에도 추가 음성 정보를 담을 수 있다.
- **실험:** 앞 1.5초 log-Mel과 전체 발화 요약 log-Mel을 결합한 `[64,48]` 특징을 구성했다.
- **판단:** 현재 ResNet 입력으로 채택했다. 시간축 평균으로 세부 변화가 약해지는 한계도 남는다.

### 넣으면 좋은 표 또는 그림

| 입력 구성 | 남기려는 정보 | 한계 |
|---|---|---|
| 앞 1.5초, 64×24 | 비교적 세밀한 시간·주파수 패턴 | 긴 발화의 뒷부분 제외 |
| 해당 발화 전체, 64×24 | 발화 전반의 에너지 분포 변화 | 평균으로 짧은 변화가 약해질 수 있음 |

그림은 동일 발화의 앞부분 Mel과 전체 요약 Mel을 좌우로 배치한다. 시간축 의미가 다름을 표시한다. 개인정보가 담긴 원음·전사 텍스트는 공개하지 않는다.

### 발표 설명

“음성 정보를 남기면서 Colab에서 반복 실험할 수 있는 크기로 만드는 것이 목표였습니다. 앞부분은 세밀하게 보고 전체는 요약했습니다. 48프레임이 연속된 음성은 아니며 sliding window도 아닙니다. 모델과 학습 조건도 함께 바뀌었기 때문에 성능 상승 전체를 전처리 하나의 효과로 설명하지는 않습니다.”

각주: 전체 통화가 아닌 JSON startAt/endAt의 한 발화. 정규화 후 uint8 저장, float32/255 복원. 실제 추론에도 동일 처리 적용.

## 3장. ResNet 선택: 작은 음향 패턴을 학습하는 기준 모델

### 슬라이드 본문

- **근거:** log-Mel은 2차원 시간·주파수 배열이므로 CNN으로 주변 음향 패턴을 학습할 수 있다.
- **가설:** 입력이 작은 만큼 첫 단계의 축소를 줄이면 필요한 패턴을 더 남길 수 있다.
- **실험:** 첫 convolution을 3×3/stride 1로 바꾸고 초기 max-pooling을 제거한 small-stem을 적용했다.
- **검증:** ResNet34 단독은 ResNet18을 넘지 못했지만 두 모델의 확률 결합은 개선됐다. 깊이 증가만으로는 해결되지 않았다.

### 넣으면 좋은 표

| 실험 | Accuracy@0.5 | 얻은 판단 |
|---|---:|---|
| ResNet18 | 91.106% | 후속 실험의 기준 모델 |
| ResNet34 | 91.030% | 더 깊다고 반드시 개선되지 않음 |
| 두 모델 50:50 | 91.419% | 단독 점수 외에 오류의 차이도 중요 |

### 발표 설명

“ResNet은 이미지 분류에서 많이 쓰이지만, 여기서는 시간·주파수 특징을 학습하는 음성 분류기로 사용했습니다. 작은 Mel 입력을 초기에 너무 줄이지 않도록 small-stem을 적용했습니다. 이후 단독 모델의 깊이보다 서로 다른 예측의 결합에서 개선을 확인했습니다.”

구조 그림 제안: Mel 3채널 반복, small-stem, residual stage 4개, global average pooling, 2개 클래스 확률. 3채널 반복은 새 정보를 만들지 않는다. ImageNet 초기화 자체의 효과나 stem 변경만의 효과를 위 표로 입증했다고 말하지 않는다.

## 4장. WavLM 저층 표현을 활용한 보완 가설

### 슬라이드 본문

- **문제:** Mel을 고정 크기로 요약하면 역할 구분에 필요한 음향 단서가 충분히 남지 않을 수 있다.
- **문헌 근거:** WavLM 연구는 화자 관련 과제에서 저층 표현의 기여를 보고한다.
- **가설:** 저층 음성 표현이 음색·발성 등 역할과 관련될 수 있는 단서를 제공해 ResNet 오류를 보완할 수 있다.
- **설계:** 앞 4개 Transformer 블록을 사용하고 블록 3·4와 분류 헤드를 미세조정했다. 계산량을 줄이면서 역할 분류에 적응시키려는 선택이다.

### 넣으면 좋은 구조 표

| 부분 | 구성과 선택 이유 |
|---|---|
| 입력 | 중앙 최대 3초 파형, 8kHz를 16kHz로 리샘플링 |
| 음성 표현 | CNN encoder와 Transformer 블록 1~4, 뒤 8개는 실행하지 않음 |
| 발화 요약 | attention 가중 평균·표준편차로 프레임 표현을 모음 |
| 학습 | Training 10만 발화, 통화 분리 내부 dev 4천 발화로 epoch 선택 |

### 발표 설명

“문헌에서 저층 표현이 화자 관련 작업에 기여한다는 점을 참고했습니다. 역할 분류에도 ResNet과 다른 단서를 제공할 수 있다고 생각했습니다. GPU 자원도 제한되어 전체 12개가 아닌 앞 4개 블록을 선택했습니다. 위급 상황의 어조가 역할과 관련될 수 있다는 것은 연구 동기이며, 긴급성을 직접 측정한 결과는 아닙니다.”

**표현 주의:** 구현은 첫 4개 블록의 마지막 출력만 사용한다. 코드 인덱스는 0~3, 출력은 hidden state 4다. hidden state 0은 첫 Transformer 이전 표현이다. '0~4층을 모두 합쳤다', '4층은 음색 전용이다', '위급 정보가 이 층에 가장 많다'고 말하지 않는다. 동일 조건의 4/8/12층 미세조정 비교가 없어 최적 층도 확정하지 않았다. 역할과 화자 신원은 다른 개념이며 낮은 층에도 내용 정보가 있을 수 있다.

발표자 노트 출처: Chen et al., *WavLM: Large-Scale Self-Supervised Pre-Training for Full Stack Speech Processing*, V-B3·V-E5 및 그림 2·3. [원 논문](https://arxiv.org/html/2110.13900v5). 문헌의 화자 관련 과제 결과를 이번 역할 분류의 가설로 확장했다.

## 5장. 가설 검증: 단독 점수보다 서로 다른 오답에 주목

### 슬라이드 본문

- **결과:** WavLM 단독 정확도는 ResNet 결합보다 낮지만 대원 Recall은 높았다.
- **추가 확인:** ResNet 결합이 틀리고 WavLM이 맞힌 발화가 3,573개였다.
- **수정한 가설:** WavLM으로 교체하기보다 두 표현의 확률을 결합하면 오류를 보완할 수 있다.
- **검증:** WavLM 25% 결합에서 Accuracy가 91.419%에서 91.819%로 높아졌다.

### 넣으면 좋은 표

| 모델 | Accuracy | 대원 Recall | 신고자 Recall |
|---|---:|---:|---:|
| ResNet18+34 | 91.419% | 86.92% | 95.59% |
| WavLM 4층 | 90.426% | 89.59% | 91.20% |
| ResNet 결합 75% + WavLM 25% | 91.819% | 87.540% | 95.785% |

여유가 있으면 오답 보완 표를 추가한다: 'ResNet 결합 오답·WavLM 정답 3,573개', 'ResNet 결합 정답·WavLM 오답 4,685개', '둘 다 오답 6,033개'. 확률을 결합한다고 3,573개를 모두 해결하는 것은 아니다.

### 발표 설명

“WavLM 단독 점수가 낮다고 실험을 끝내지는 않았습니다. 대원을 더 잘 맞히는 대신 신고자를 더 자주 놓쳤고 실제 맞히는 발화도 달랐습니다. 단순 교체 대신 확률을 결합했습니다. 결과는 보완 가설을 지지하지만, 개선 원인이 구체적으로 음색인지 어조인지까지 밝혀주지는 않습니다.”

각주: 동일 전체 Validation, threshold 0.5. 두 방법의 학습량·입력·학습 대상은 달라 모델 구조 자체의 우열 비교는 아니다. 초기 고정 임베딩의 검증 2,000개 실험과 혼합하지 않는다.

## 6장. 결합 비율 검증과 현재 선택

### 슬라이드 본문

- **질문:** WavLM 비중을 높이면 오류 보완이 계속될까?
- **실험:** ResNet18:34는 1:1로 두고 WavLM 비중 15~60%를 비교했다. 임계값은 모두 0.5였다.
- **검증:** 40%가 비교 범위 내 최고였다. 이후에는 신고자 Recall 하락이 커져 전체 정확도가 낮아졌다.
- **현재 선택:** ResNet18 30%, ResNet34 30%, WavLM 40%. Accuracy **91.972%**, 대원 Recall **87.990%**, 신고자 Recall **95.663%**.

### 넣으면 좋은 표 또는 선 그래프

| WavLM 비중 | Accuracy | 대원 Recall | 신고자 Recall |
|---|---:|---:|---:|
| 25% | 91.819% | 87.540% | 95.785% |
| **40%** | **91.972%** | **87.990%** | **95.663%** |
| 45% | 91.954% | 88.179% | 95.453% |
| 60% | 91.181% | 88.160% | 93.980% |

그래프는 x축 WavLM 비중, y축 Accuracy(%)로 표시한다. 일부 조건만 표시할 때는 '대표 조건'이라고 적는다. 40%와 45%의 작은 차이를 과장하는 축이나 장식은 피한다. 전체 비율 표는 [결과 문서](results/resnet_wavlm_ensemble_20261011/README.md)에 있다.

### 발표 설명

“WavLM을 더 많이 넣는다고 항상 좋아지지는 않았습니다. 대원 개선과 신고자 손실을 함께 보니 이번 검증에서는 30:30:40이 가장 높았습니다. 45%와는 정답 20개 차이여서 새로운 데이터에서도 이 비율이 최적이라고 주장하지는 않습니다.”

슬라이드 하단 필수 주석: **반복 사용한 공식 Validation의 모델 선택 결과이며 독립 Test 성능이 아님.** WavLM 소수점 6자리 CSV 확률을 사용한 결합이므로 실제 세 가중치 통합 추론 재검증이 필요함.

발표자 노트: ResNet에는 과거 튜닝 점수로 epoch를 선택한 이력이 있다. 현재 판정은 0.5지만 그 선택 이력의 허용 여부는 주최 측 확인 대상이다. 30만 발화 WavLM은 데이터·코드만 준비했으며 현재 기록에 포함하지 않는다. 94% 달성이나 위급도 검출을 주장하지 않는다.

## 7장. 사회안전 시사점: 역할별 신고 기록을 돕는 보조 기술

### 슬라이드 본문

**기대하는 활용**

- 대원의 질문·안내와 신고자의 설명을 역할별로 정리해 신고 기록 검토와 후속 분석을 보조할 수 있다.
- 역할 구분을 후속 대화 분석의 입력으로 활용할 가능성이 있다. 실제 업무 시간 단축 효과는 아직 측정하지 않았다.

**안전하게 활용하기 위한 조건**

- 역할 오분류는 '누가 말했는지'를 바꾼다. 사람이 원음과 결과를 확인할 수 있도록 하고 출동·위급도 판단을 이 모델에 맡기지 않는다.
- 다른 지역·새 화자·통신 환경에서 추가 검증하고 음성·사건 정보의 접근 권한과 보관 범위를 제한해야 한다.

**결론:** 서로 다른 음성 표현의 결합으로 역할 분류 오류를 줄일 가능성을 확인했다. 실제 도입에는 별도 성능 검증과 사람의 확인 절차가 필요하다.

### 넣으면 좋은 표

| 활용 가능성 | 함께 관리할 위험 |
|---|---|
| 대원 안내와 신고자 진술의 역할별 기록 | 역할이 뒤바뀌어 내용 해석에 영향을 주는 오류 |
| 신고 기록 검토·후속 분석 보조 | 새 환경의 성능 저하, 민감한 음성 정보 노출 |

### 발표 설명

“역할 구분은 신고 기록 검토를 도울 수 있습니다. 다만 이 모델은 위급도를 판단하거나 출동을 결정하지 않습니다. 오분류가 후속 해석에 영향을 줄 수 있으므로 사람이 확인하는 보조 기능으로 활용하고, 현장 일반화와 개인정보 보호를 함께 검토해야 합니다.”
