## 1. 과제 이해와 입력 범위

출제문제는 AI-hub의 119 신고접수 음성·전사 데이터를 사용해 사회안전 문제를 다루도록 요구한다. Mission 3의 지정 입력은 신고자 및 119대원의 대화 텍스트이며 전사 외 라벨링 데이터는 입력으로 사용할 수 없다. 지정 증상은 고열, 구토, 두통, 복통, 어지러움, 열상, 오심, 전신쇠약, 호흡곤란이다. 통화마다 0~9개의 증상을 출력하므로 단일 클래스 분류가 아니라 9개 이진 판단의 결합으로 구성했다.

원본 symptom 목록에서 대상 외 라벨을 제외하되 샘플 자체는 제거하지 않았다. 출력이 없는 통화도 정상적인 예측 대상이다. speaker, recordId, audioPath, 주소 및 증상 정답을 입력 문자열에 넣지 않았다. 통화 식별자는 파일 대응과 검증 순서 확인에만 사용했다. 음성 파일을 추가 입력하는 방식은 이번 Mission 3 실험에 포함하지 않았다.

질문과 답변이 섞인 전사에서는 증상 단어의 존재와 환자의 실제 증상 여부가 다를 수 있다. 예를 들어 “토할 것 같아요”와 “토는 안 했어요”를 동일한 구토 표현으로 처리하면 잘못된 판단을 만들 수 있다. 이 예시는 실제 오답에서 인용한 사례가 아니라 문제 구조를 설명하기 위한 예시다. 간접 표현·부정·대화의 주어는 후속 오류 분석 대상으로 두었고, 확인하지 않은 원인을 확정적으로 서술하지 않았다.

## 2. 데이터 분석과 실험 기준

서울 Training 29,200건을 내부 학습 23,408건과 내부 검증 5,792건으로 나눴다. 공식 Validation 3,640건은 학습에 사용하지 않았다. 성능 표의 수치는 별도 표시가 없는 한 내부 검증 결과다. 비교에 사용한 분할 파일과 정답·파일 순서를 확인했고, 결합 시에는 타깃 순서와 예측 행이 일치하는지도 검사했다.

기존 EDA 기록에서 여러 증상이 함께 나타나는 통화를 확인했다. 전체 Training 중 증상 1개는 19,560건, 2개는 7,137건, 3개 이상도 존재했다. 이 통계는 대상 라벨의 결합 구조를 설명하지만 증상 동시 발생만으로 다른 증상을 강제 추가하는 규칙은 만들지 않았다. 상관관계를 개별 환자의 증상 근거로 대체하지 않기 위해서다.

초기 raw 토큰화 통계에서는 Training의 512토큰 초과 비율이 약 2.7%였다. 발화 SEP를 넣은 후속 문맥 실험에서는 내부 학습 4.6%, 내부 검증 5.4%가 512토큰을 넘었다. 전처리와 집계 대상이 다르므로 두 값을 동일한 통계로 사용하지 않는다. 긴 통화가 일부 존재한다는 사실은 문맥 보존 실험의 근거지만 전체 오류가 입력 잘림 때문이라는 결론의 근거는 아니다.

과거에는 임계값 조정을 탐색했으나 멘토링 이후 후속 비교와 판정은 0.5로 고정했다. 출제 PDF에는 임계값 0.5 조항이 명시돼 있지 않으므로 이를 PDF 규정으로 인용하지 않는다. 과거 튜닝 최고 0.6562는 현재 고정 0.5 성능표에서 제외했다. 또한 Macro F1은 통화 단위 Accuracy가 아니며 0.650944를 통화의 65.09%를 맞혔다고 해석하지 않는다.

## 3. 모델과 전처리 설계

### 3.1 KLUE-RoBERTa

전사 발화 사이에 SEP 토큰을 넣어 문장 경계를 보존하고, 최대 512토큰을 입력했다. 기본 First-512는 특수 토큰을 제외한 앞 510개 내용 토큰을 사용한다. Head-Tail과 앞·뒤 두 창 방식은 별도 실험 조건으로 구분했다. 정답 증상에 따라 입력을 다르게 고르지 않았고 검증 전용 처리를 만들지 않았다.

RoBERTa 인코더는 문맥을 반영한 토큰 표현을 만들고, label-attention head는 증상별 가중합으로 분류 입력을 구성한다. 각 증상의 logit에 sigmoid를 적용하고 0.5 이상이면 해당 증상을 출력한다. RoBERTa와 head를 함께 학습했다. Attention head를 추가한 것은 backbone을 다른 모델로 교체한 것이 아니다. Attention 가중치의 의학적 설명력은 별도로 검증하지 않았다.

### 3.2 TF-IDF

TF-IDF는 전체 전사를 연결한 텍스트에서 문자 2~5그램을 추출한다. 2-5에서는 min_df 2, 최대 특징 150,000, sublinear TF와 증상별 Logistic Regression을 사용했다. 분류기는 C=2, liblinear, max_iter=1,000으로 학습했고, vectorizer와 가중치는 내부 학습 데이터에서만 계산했다.

가중 TF-IDF의 양성 가중치는 `clip(sqrt(negative/positive),1,3)`이다. RoBERTa W1의 세 증상 추가 1.25배 규칙과는 다르다. 문자·단어 특징 결합도 비교했지만 현재 최고에는 문자 TF-IDF만 포함한다. TF-IDF가 원문 전체를 사용하는 점과 RoBERTa의 문맥 표현을 함께 평가했으며, 각각의 역할을 인과적으로 분리한 실험은 아니다.

### 3.3 손실과 결합

가중 BCE는 양성 증상을 놓치는 학습 비용을 높인다. 기본 W0는 음성·양성 비율의 제곱근을 1~3으로 제한한다. W1은 두통·오심·전신쇠약에 1.25배를 추가 적용하고 상한을 4로 둔다. 이는 학습 손실 변경이며 예측 임계값 변경이 아니다.

현재 최고 조합의 확률은 다음과 같다.

```text
A = (Base_seed42 + Base_seed123 + Base_seed2026) / 3
B = 0.5 * A + 0.5 * Large_seed42
최종 확률 = 0.8 * B + 0.2 * 가중 문자 TF-IDF
증상 판정 = 최종 확률 >= 0.5
```

개별 Base의 최종 비중은 각각 2/15, Large는 0.4, TF-IDF는 0.2다. 저장된 모델 가중치를 평균한 것이 아니므로 새 데이터 추론에는 모든 구성 모델이 필요하다.

## 4. 실험 과정과 의사결정

### 4.1 Head와 발화 경계

동일 조건 head 비교에서는 CLS 0.610240, Mean 0.611556, Label attention 0.614364를 기록했다. 별도의 전처리 비교에서는 raw 0.6075, 발화 경계 보존 0.6114였다. 각각 단일 변경 실험에서 소폭 개선을 관측했지만, 서로 다른 실행의 개선 폭을 더해 최종 효과로 계산하지 않았다. 이후 경계와 증상별 Attention을 기준 설정으로 사용했다.

### 4.2 가중 BCE의 개선과 비용

일반 BCE와 가중 BCE의 통제 실험에서는 전체 Macro F1이 약 0.6107에서 0.6400으로 높아졌다. 오심 TP는 75에서 241로 늘고 FN은 593에서 427로 줄었다. 반면 FP는 72에서 435로 늘고 precision은 0.5102에서 0.3565로 낮아졌다. 가중 학습은 누락을 줄였지만 정답 라벨 기준 음성(negative) 사례를 양성으로 예측하는 비용을 동반했다.

추가 W1 가중치를 세 seed에서 비교한 결과 W0 평균은 0.637379, W1 평균은 0.640013이었다. W1의 전체 F1은 세 seed 모두 높았지만 두통 F1은 모두 낮았다. 오심 평균 recall은 0.3802에서 0.4571로 상승하고 precision은 0.3424에서 0.3212로 하락했다. 따라서 재현율과 전체 분류 균형은 같은 목표가 아니라는 점을 확인했다.

### 4.3 문맥 확대와 모델 크기

Head-Tail 직접 비교에서는 First-512 재학습 0.6387, Head-Tail 0.6382였다. 긴 검증 통화 313건에서는 First-512 0.6520, Head-Tail 0.6276으로 나타났다. 앞부분과 중간 맥락의 손실이 영향을 줬을 가능성이 있지만 원인으로 확정하지 않았다. 두 창 모델도 0.637320으로 기존 W1 Base를 넘지 못했다. 이 방식은 창별 logit을 평균하므로 두 창의 발화 관계를 공동으로 학습하는 전체 대화 모델과는 다르다.

Large W1은 0.637518로 Base W1 seed42의 0.640102보다 낮았다. Large는 micro batch 2·누적 4, 과거 Base는 batch 8·누적 1이므로 크기 하나만의 효과로 해석할 수 없다. 반대로 Large를 다른 seed Base와 결합한 실험에서는 개선을 관측했다. 단독 점수와 결합에 필요한 보완성을 구분했다.

### 4.4 현재 최고와 이후 탐색

| 실험 | 조건 | 내부 검증 Macro F1 | 결정 |
|---|---|---:|---|
| 2-4 A | Base W1 세 seed 확률 평균 | 0.645129 | 결합 기준 후보 |
| 2-4 B | A·Large 50:50 | 0.647423 | TF-IDF 결합 기준 |
| 2-5 | B 80%·가중 문자 TF-IDF 20% | **0.650944** | 현재 최고 유지 |
| 2-6 | 문자·단어 TF-IDF로 대체 | 0.650060 | 기존 문자 구성 유지 |
| 2-8 | 최고 80%·두 창 모델 20% | 0.650801 | 교체하지 않음 |
| 2-9 | R-Drop Base 단독 | 0.640420 | 앙상블 보완 여부 별도 확인 |

2-5에서 가중 TF-IDF는 단독 0.573397이었지만 기존 B에 결합하면 0.003522 높아졌다. 단독 성능이 낮다는 이유로 제외하지 않고 실제 결합 결과를 확인한 점이 중요하다. 같은 B와 80:20 비율을 유지한 비교에서는 일반 TF-IDF 결합 0.648975에서 가중 TF-IDF 결합 0.650944로 0.001969 높아졌다. 이 비교는 TF-IDF 가중 학습의 효과를, B 단독과의 비교는 TF-IDF 추가의 효과를 보여주므로 두 개선 폭을 혼용하지 않는다. 개별 통화의 오류 보완 건수는 이 집계 비교만으로 산출하지 않았다.

채택 기준은 새 방법의 복잡성이 아니라 실제 결합 점수였다. 두 창 추가는 최고 대비 0.000144, R-Drop 추가는 0.000304 낮아 2-5를 유지했다. 추가 모델의 추론 비용을 정당화할 개선을 관측하지 못했으며, 실행 시간 절감 효과를 측정했다는 뜻은 아니다.

R-Drop은 같은 입력을 다른 dropout으로 두 번 계산해 출력 일관성을 높이는 정규화를 적용했다. 2-9는 alpha 1.0, 독립 sigmoid 라벨에 대한 Bernoulli 대칭 KL을 사용했다. 과거 W1보다 0.000319 높았으나 실행 배치 방식이 달라 순수 정규화 효과로 단정할 수 없다. 2-10은 학습 전에 제안한 고정 80:20 결합을 평가한 결과이며 추가 비율 탐색은 하지 않았다.

## 5. 증상별 실패와 정성적 해석

현재 최고 2-5에서 오심 F1은 0.3763, 두통은 0.5262, 전신쇠약은 0.5873이다. 열상 0.8914와 복통 0.8002보다 낮다. 이 차이는 오류가 증상별로 균등하지 않음을 보여주지만 어떤 표현이 원인인지는 집계 수치만으로 확인할 수 없다.

오심의 실제 양성 668건 중 TP 263, FN 405이며 FP도 467건이다. 2-10에서 TP는 265로 두 건 늘었으나 FP는 490으로 23건 늘었다. recall은 0.3937에서 0.3967로 상승했지만 precision은 0.3603에서 0.3510으로 낮아져 F1은 0.3763에서 0.3725로 하락했다. “더 많이 찾았다”는 사실과 “더 잘 구분했다”는 사실을 구분해야 하는 사례다.

정성 분석의 후속 질문은 환자가 호소한 증상과 대원이 확인을 위해 언급한 증상을 혼동하는지, 부정·유보 표현을 어떻게 처리하는지, 다른 사람의 증상을 환자의 증상으로 오인하는지다. 멘토링에서 언급한 발화 겹침이나 텍스트 근거 부족도 가설로 보관한다. 그러나 원음·원문과 라벨을 대조하지 않은 사례를 오류 원인으로 확정하거나 오심을 관측만으로 맞출 수 없는 증상이라고 단정하지 않는다. 음성 겹침별 모델 학습도 완료한 실험으로 포함하지 않는다.

| 현재 확인한 사실 | 가능한 설명 — 아직 미확인 | 후속 확인 방법 |
|---|---|---|
| 오심 누락 405건 | 간접 표현·잘린 문맥·전사 근거 부족 | FN 전사와 정답을 대조하고 표현·길이별로 분류 |
| 오심 오탐 467건 | 질문·부정·다른 사람의 증상 혼동 | FP에서 증상 언급의 주어와 긍정 여부 확인 |
| 가중 학습에서 TP와 FP가 함께 증가 | 양성 탐지 강화와 구분 능력 개선이 일치하지 않음 | 동일 설정에서 가중치 강도만 비교하고 precision·recall 동시 확인 |

표의 설명은 실제 사례 분석 결과가 아니라 분석 계획이다. 정성 보고에서는 사례를 확인한 뒤 관측 근거와 해석을 나누어 기록한다. TP·FP의 차이는 집계 건수 차이이며 동일 사례의 전환 내역을 추적한 결과와 구분한다.

2-11은 동일 seed 42·초기값·입력·실행 설정에서 세 증상 추가 가중치 1.25배와 1.10배를 비교했다. R-Drop은 제외했다. 전체 Macro F1은 0.639782에서 0.638900으로 0.000882 하락했다. 오심 FP는 638건에서 540건으로 줄었으나 FN은 367건에서 401건으로 늘었다. 오심 precision은 0.3206에서 0.3309로 상승했지만 recall은 0.4506에서 0.3997로, F1은 0.3746에서 0.3620으로 하락했다. 두통 F1은 소폭 개선됐으나 오심·전신쇠약 F1은 하락해 세 증상 가중치 완화를 채택하지 않았다. 한 seed의 내부 검증 결과이며 TF-IDF 결합은 평가하지 않았다.

최종 단계에서는 최고 2-5 설정을 다시 학습하고 공식 Validation 3,640건을 한 번 평가했다. 공식 Validation은 학습·가중치 계산·epoch 선택·비율 탐색에 사용하지 않았다. 재학습 점수는 과거 0.650944와 별도로 기록했다. Base 3개, Large, TF-IDF, 평가 결과, 코드 TAR와 실행 로그 노트북을 로컬 Downloads에서 확보했고 모델 TAR의 내부 SHA256 검증을 통과했다.

## 6. 실패 실행의 처리와 재현성

초기 손실 비교에서 F1이 0이고 손실이 비정상적으로 작아진 실행이 있었다. 보고서에 보관된 점검에서는 non-persistent 양성 가중치 buffer가 로딩 후 기대값과 달라지는 현상을 작은 모델로 재현했다. 수정본은 config에 숫자를 보관하고 실제 계산 장치에서 가중치를 생성했다. 독립 BCE 식, 양성 라벨 포함 입력, 저장·재로딩 일치, 비정상 gradient 검사를 추가했다. 해당 실패 실행을 유효한 모델 성능으로 집계하지 않았다.

학교 Drive 용량 부족과 Colab 연결 단절은 모델 성능과 별개의 실행 문제였다. 결과는 로컬 TAR로 보관하고 Git에는 집계 지표·설정·학습 로그를 공유했다. 체크포인트는 같은 VM에서 재개할 수 있으나 /content는 영구 저장소가 아니다. 모델 가중치와 작은 결과 백업도 다른 자료다. 예측 배열이 있어도 새 데이터 추론이나 학습 재개를 대신할 수 없다.

## 7. 사회안전 활용 시사점

활용을 검토할 수 있는 형태는 신고접수자가 다시 확인할 증상 후보를 제안하는 보조 기능이다. 누락된 증상은 확인 질문의 기회를 줄일 수 있고, 오탐은 불필요한 질문과 검토 부담을 늘릴 수 있다. 두 오류의 운영 비용은 이번 실험에서 측정하지 않았다. 따라서 비용을 임의로 수치화하거나 정확도가 높아 현장 도입이 가능하다고 주장하지 않는다.

운영 설계에서는 모델의 예측과 전사 원문을 함께 제시하고 담당자의 최종 확인을 남기는 방식이 필요하다. 낮은 확률을 증상 부재의 확정 증거로 사용해서는 안 된다. 특히 오심의 낮은 recall을 고려하면 출력 목록에 없다는 이유로 추가 확인을 생략하는 사용은 위험할 수 있다. 이 내용은 활용 시 고려사항이며 실제 운영 효과를 검증한 결과가 아니다.

| 실험에서 확인한 한계 | 활용 시 예상되는 문제 | 제안하는 확인 절차 — 미검증 |
|---|---|---|
| 오심 양성 668건 중 405건 누락 | 후보 목록만 보면 확인할 증상을 놓칠 수 있음 | 목록에 없음을 증상 부재로 처리하지 않고 담당자가 원문·응답 확인 |
| 오심 오탐 467건 | 불필요한 확인과 잘못된 증상 기록 가능성 | 모델 후보와 확인된 증상을 분리하여 표시·기록 |
| 증상별 F1의 큰 차이 | 평균 점수로 모든 증상을 동일하게 신뢰할 수 있음 | 증상별 성능·평가 범위를 함께 공개 |

자동 진단, 중증도 판정, 출동 우선순위 결정은 이번 모델의 평가 대상이 아니다. 신고 대응 시간 단축이나 환자 결과 개선도 측정하지 않았다. 실제 적용 전에는 별도 데이터에서의 성능, 기록 품질 변화, 현장 사용자 검토 부담을 확인해야 한다. 통화 전사·파일 식별자는 민감한 정보를 포함할 수 있어 공개 자료에서는 개별 기록을 제외하고 집계 결과 중심으로 공유했다.

## 8. 팀 전체 결과와의 연결

Mission 1 팀원은 정답 신고자 구간을 사용한 통화 단위 성별 분류에서 WavLM 특징과 Logistic Regression을 평가했다. Mission 2는 한 발화의 음성 특징으로 신고자·119대원 역할을 분류했다. Mission 3는 대화 전사로 여러 증상을 판정한다. 각 미션의 지표와 데이터 단위가 달라 수치를 직접 순위화하지 않는다.

팀원의 문서에서 참고한 공통 원칙은 단독 성능 순위와 보완성을 분리하는 것, 한 집단의 recall 개선과 전체 성능의 교환관계를 확인하는 것, 결과를 보고 기존 모델을 유지할 수 있다는 점이다. Mission 1의 MFCC 보완 분석과 Mission 2의 대원 가중치 trade-off를 참고해 Mission 3도 가설·통제 조건·관측·판단을 분리해 서술했다. 다른 미션의 입력이나 모델을 Mission 3에 사용한 것은 아니다.

## 9. 평가 한계와 제출 준비

내부 검증 점수는 여러 차례 반복 사용한 개발 자료의 탐색 성능이다. 공식 Validation 결과는 0.647617이며, 비공개 Test 일반화 성능·통계적 유의성·현장 효과는 확인하지 않았다. 일부 역사적 비교에서는 실행 환경·정밀도·배치 방식 등이 달랐으며, 이를 단일 요인 효과로 주장하지 않는다.

출제문제 11쪽은 미션별 단일 실행 명령을 요구한다.

```bash
python inference.py --audio_dir {wav_folder} --label_dir {json_folder} --ckpt_path {checkpoint_file} --output ./outputs/mission3.csv
```

Mission 3는 공통 인자를 받으며 지정 전사 텍스트만 처리한다. 결과는 `[label file name], [symptom]` 의미 구조에 맞춰 `file_name,symptom` 컬럼과 JSON 문자열 목록으로 저장한다. 빈 목록 표현은 `[]`이다. 단일 ckpt_path 인자로 ensemble.json을 받아 네 RoBERTa와 TF-IDF 객체를 찾는 복원 패키지를 실제 실행해 확인했다. 제공 PDF에는 정확한 헤더 문자열·목록 직렬화 방식이나 실행형 채점기가 포함되지 않았다.

제출 산출물 및 최종 점검:

- [x] 최종 후보와 0.5 판정 규칙 고정, 내부 및 공식 Validation 결과 기록.
- [x] Base 세 모델·Large 모델의 `.pt` 가중치와 config·tokenizer 포함 TAR 확보.
- [x] TF-IDF vectorizer와 증상별 Logistic Regression 객체 포함 TAR 확보.
- [x] 각 모델의 저장·재로딩 일치 검사 및 내부 검증 예측 저장.
- [x] 로그 포함 `.ipynb`, 모델 코드와 `requirements.txt` 확보.
- [x] 제출 규칙의 단일 `inference.py` 명령과 출력 컬럼 `[label file name], [symptom]`을 원본 PDF와 대조.
- [x] 새 가상환경에서 오프라인 단일 추론 명령 실행. 실제 Validation 7건은 정답 필드를 제거한 상태에서 기존 예측과 일치했고, 빈 전사·긴 전사 2건도 정상 처리했다.
- [x] CSV 파일명·증상 목록 구조, UTF-8 인코딩, 중복 파일명 및 대상 증상 범위 검사. 제공 PDF는 정확한 헤더 문자열·목록 직렬화 방식까지 지정하지 않아 `file_name,symptom`과 JSON 문자열 목록으로 명시했다. 별도 실행형 채점기는 제공되지 않았다.

이 평가에는 비공개 Test 점수가 포함되지 않는다. 새 환경 복원 검수는 표본 7건과 경계 입력 2건으로 수행했으며, 저장된 내부 검증 5,792건·공식 Validation 3,640건의 확률로 Macro F1을 재계산해 일치함을 확인했다.
